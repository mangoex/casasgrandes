# ADR-009 — Precio mensual y presupuesto total de descuento

- Estado: aprobado para implementación local en `CHG-009`
- Fecha: 2026-08-27
- Aprobación: responsable de producto en conversación del cambio

## Contexto

El catálogo conserva el precio base anual y Programación define un precio efectivo por mes y un tope promocional. El Cotizador trataba el tope completo como descuento adicional del asesor, aunque parte de ese presupuesto ya estaba incorporada al reducir el precio mensual frente al catálogo.

## Decisión

- `productos.list_price_mxn` es el precio base anual de referencia.
- `crm_precios_mensuales.precio` es el precio base operativo del mes y el valor de lista que se muestra y persiste al cotizar.
- La reducción mensual consumida es `max(precio_anual - precio_mensual, 0)`.
- `promo_dinero` o `promo_porcentaje` representa el presupuesto total de descuento desde el precio anual; el porcentaje se calcula sobre el precio anual.
- El saldo adicional del asesor es `max(tope_total - reducción_mensual, 0)` y nunca puede dejar el precio final por debajo de cero.
- Volumen, temporada y Cuenta Clave conservan sus contratos actuales y no consumen ese saldo.
- Si la reducción mensual excede el tope total, Programación rechaza el guardado y el Cotizador falla cerrado ante configuraciones heredadas inválidas.
- El servidor es autoridad para el cálculo y rechaza descuentos cliente superiores al saldo; la interfaz solo refleja el contrato.
- El runtime productivo calcula dinero en centavos enteros. Python `Decimal` con redondeo `ROUND_HALF_UP` actúa como oráculo de pruebas compartidas, no como segundo servicio productivo.

## Alternativas descartadas

- Tratar la promoción mensual como descuento adicional: duplicaría capacidad comercial.
- Mantener la reducción mensual como movimiento del slider: ocultaría el precio operativo real.
- Invocar Python como servicio en cada cotización: añadiría un segundo runtime y otra frontera de fallo sin necesidad.

## Consecuencias

- El precio mensual aparece como lista en Cotizador y PDF.
- El asesor ve únicamente el saldo adicional disponible.
- Previsualización, alta, edición, planificación y Outreach deben compartir el mismo resolvedor.
- Las cotizaciones históricas no se recalculan; las nuevas conservan un snapshot del contrato aplicado.
