# ADR-008 — Salud, observabilidad y ciclo de vida

- Estado: aprobado para `CHG-008`
- Fecha: 2026-07-27

## Contexto

El proceso no ofrece sondas para distinguir vida de disponibilidad, carece de correlación HTTP y no coordina el cierre del servidor, scheduler y PostgreSQL.

## Decisión

- Separar liveness, sin dependencias, de readiness, con consulta PostgreSQL acotada.
- Validar o generar `X-Request-ID` y registrar un evento JSON mínimo al terminar cada respuesta.
- Tratar query strings, cuerpos e identidad como datos no autorizados para el log HTTP.
- Ejecutar un cierre idempotente: detener aceptación y scheduler, esperar actividad y cerrar el pool.
- Aplicar un timeout global; si se excede, marcar salida fallida sin declarar cierre limpio.

## Consecuencias

- El orquestador puede retirar una réplica degradada sin reiniciar procesos que siguen vivos.
- Las solicitudes pueden correlacionarse sin convertir logs en una copia de PII.
- El cierre local es verificable; Gate 5 exige probar señales, drenado y rollback en staging.
