# ADR-003 — Transacciones y bloqueos pesimistas

- Estado: aprobado para `CHG-003`
- Fecha: 2026-07-27

## Contexto

Inventario, producción UAN-32, entrega de cotizaciones y decisiones de puja leen un estado y luego escriben varias filas mediante conexiones independientes. Un fallo o dos peticiones concurrentes pueden producir saldos, estados o asignaciones incompatibles.

## Decisión

- Usar una única conexión PostgreSQL con `BEGIN/COMMIT/ROLLBACK` por operación compuesta.
- Bloquear con `FOR UPDATE` el producto, cotización, puja o cliente antes de calcular.
- Ordenar bloqueos de productos por ID para reducir deadlocks.
- Revalidar estado dentro de la transacción.
- Tratar el estado persistido como clave natural de idempotencia para transiciones.

## Consecuencias

- Los controladores enviarán respuesta solo después de `COMMIT`.
- Un fallo intermedio revierte todos los efectos.
- Una petición concurrente espera y después revalida el estado actualizado.
- La idempotencia por clave externa para movimientos manuales queda para un incremento posterior.
